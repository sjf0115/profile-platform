# 通知插件体系架构重构与扩展

## 核心决策
- API 层 SLA 前缀 -> 通用 Notification 语义全面重命名
- 引入简单模板机制支持不同通知场景
- 新增钉钉、企业微信插件，统一 HTTP 调用方式
- 启用 Spring 集成，使通知模块可被业务层调用

## Task 1: API 层重命名（去 SLA 化）

将所有 SLA 前缀类重命名为通用通知语义，涉及以下文件：

| 原类名 | 新类名 | 文件路径 |
|--------|--------|----------|
| `SlasHandlerPlugin` | `NotificationHandlerPlugin` | `profile-notification-api/.../spi/` |
| `SlaSenderMessage` | `NotificationSenderConfig` | `profile-notification-api/.../entity/` |
| `SlaConfigMessage` | `NotificationReceiverConfig` | `profile-notification-api/.../entity/` |
| `SlaNotificationMessage` | `NotificationMessage` | `profile-notification-api/.../entity/` |
| `SlaNotificationResult` | `NotificationResult` | `profile-notification-api/.../entity/` |
| `SlaNotificationResultRecord` | `NotificationResultRecord` | `profile-notification-api/.../entity/` |

同时更新所有引用这些类的文件（core 层、plugin 层）。

## Task 2: 基于 FreeMarker 的通知模板机制

项目已有 FreeMarker 使用先例（`SqlTemplateEngine` + `label_distribution.ftl`），通知模板复用同一技术栈。

### 2.1 NotificationTemplate 枚举（API 层）
文件: `profile-notification-api/.../enums/NotificationTemplate.java`
```java
public enum NotificationTemplate {
    ALERT("alert", "告警通知"),
    USER_INVITATION("user_invitation", "用户邀请"),
    TASK_COMPLETE("task_complete", "任务完成通知"),
    CUSTOM("custom", "自定义");
    
    private final String templateName; // 对应 .ftl 文件名（不含后缀）
    private final String description;
}
```

### 2.2 NotificationTemplateEngine（Core 层）
文件: `profile-notification-core/.../engine/NotificationTemplateEngine.java`
- 使用 FreeMarker `Configuration` 加载 `notification-templates/` 目录下的 .ftl 模板
- `render(NotificationTemplate template, Map<String, Object> params)` -> 渲染为字符串
- 参考 `SqlTemplateEngine` 的实现模式（`@PostConstruct` 初始化 + `render` 方法）

需在 `profile-notification-core/pom.xml` 中新增 freemarker 依赖。

### 2.3 具体场景 .ftl 模板文件
文件目录: `profile-notification-core/src/main/resources/notification-templates/`

**alert.ftl** - 告警通知（任务失败、数据异常等）
```
【告警】${title}
时间: ${timestamp}
级别: ${level}
详情: ${detail}
```

**user_invitation.ftl** - 用户邀请注册
```
${inviterName} 邀请您加入 ${platformName}
请点击以下链接完成注册：
${activationUrl}
该链接 ${expireHours} 小时后失效。
```

**task_complete.ftl** - 任务完成通知
```
【任务完成】${taskName}
状态: ${status}
开始时间: ${startTime}
结束时间: ${endTime}
详情: ${detailUrl}
```

### 2.4 NotificationMessage 增加 template 字段
在 `NotificationMessage` 中增加 `NotificationTemplate template` 和 `Map<String, Object> templateParams` 字段。

### 2.5 邮件渠道 HTML 包装模板
文件: `notification-templates/email_wrapper.ftl`
为邮件渠道提供 HTML 外壳包装（表格布局 + 品牌标题），IM 渠道（钉钉/企微）直接使用纯文本/markdown 模板输出。

```java
// 简单单发：指定渠道 + 收件人配置 + 主题 + 内容

```

## Task 5: 新增钉钉通知插件

### 5.1 模块结构
```
profile-notification-plugins/profile-notification-plugin-dingtalk/
  pom.xml
  src/main/java/com/data/notification/plugin/dingtalk/
    DingTalkConstants.java
    DingTalkSender.java            -- HmacSHA256 签名 + HttpClient POST
    DingTalkNotificationHandlerPlugin.java
    entity/ReceiverConfig.java     -- webhook, secret, keyword, atMobiles, atDingtalkIds, isAtAll
  src/main/resources/META-INF/plugins/
    com.data.notification.api.spi.NotificationHandlerPlugin
```

### 5.2 DingTalkSender 关键实现（参考 datavines，适配项目 HttpClient）
- `constructUrl()`: HmacSHA256 签名 URL（commons-codec 已在 profile-common 中）
- `generateMsgJson()`: 支持 text/markdown，支持 @手机号/@钉钉ID/@所有人
- 使用 Apache HttpClient 4.x 发送 POST（已在 profile-common 中）

### 5.3 SPI 注册
- `dingtalk=com.data.notification.plugin.dingtalk.DingTalkNotificationHandlerPlugin`
