# 标签体系化设计方案

## 核心概念区分

### 1. 三种标签类型

| 类型 | 定义 | 存储位置 | 用途 |
|------|------|---------|------|
| **标签元数据** | 标签的定义（名称、类目、类型等） | `profile_meta_label` | 标签管理模块维护 |
| **打标标签** | 用户实际拥有的标签及值 | `profile_user_label` | 用户画像详情页展示 |
| **展示标签配置** | 全局配置哪些标签在详情页展示 | 新增表 `profile_label_display_config` | 控制详情页显示范围 |

### 2. 关系说明

```
标签元数据 (profile_meta_label)
    ↓ 关联
打标标签 (profile_user_label) -- 用户实际拥有的标签值
    ↓
展示标签配置 (profile_label_display_config) -- 全局配置，控制哪些标签在详情页显示
```

**关键问题解答**：
- **打标标签与正常标签的关系**：打标标签是标签元数据的实例化，一个标签元数据可以被多个用户打标
- **打标标签如何存储**：`profile_user_label` 表，记录 user_id + label_id + label_value
- **是否会被正常标签覆盖**：不会，打标标签是用户维度的，标签元数据是全局的
- **展示标签的作用**：全局配置，控制所有用户画像详情页显示哪些标签维度

## 数据库设计

### 新增表：标签展示配置表（全局）

```sql
DROP TABLE IF EXISTS `profile_label_display_config`;
CREATE TABLE `profile_label_display_config` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键 ID',
  `label_id` VARCHAR(64) NOT NULL COMMENT '标签 ID（关联 profile_meta_label.label_id）',
  `category_id` VARCHAR(64) NOT NULL COMMENT '类目 ID（冗余字段，便于查询）',
  `display_order` INT DEFAULT 0 COMMENT '展示排序',
  `is_enabled` INT NOT NULL DEFAULT 1 COMMENT '是否启用：1-启用，0-禁用',
  `gmt_create` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `gmt_modified` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_label_id` (`label_id`),
  KEY `idx_category_id` (`category_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='画像 - 标签展示配置表（全局）';
```

**设计理由**：
- 全局配置表，不与用户维度耦合
- 管理员统一设置哪些标签在画像详情页展示
- 支持启用/禁用控制
- 支持自定义展示顺序

## 后端接口设计

### 1. 获取展示标签配置（全局）

```
GET /insight/user-profile/label-display-config
```

**响应**：
```json
{
  "code": 0,
  "data": {
    "categories": [
      {
        "category_id": "0700000000000001",
        "category_name": "未分类",
        "labels": [
          {
            "label_id": "label_001",
            "label_name": "gender",
            "is_enabled": true
          }
        ]
      }
    ]
  }
}
```

### 2. 保存展示标签配置（全局）

```
POST /insight/user-profile/label-display-config
```

**请求体**：
```json
{
  "displayLabelIds": ["label_001", "label_002", "label_003"]
}
```

### 3. 获取用户画像详情（含打标数据）

```
GET /insight/user-profile/{userId}
```

**响应**：
```json
{
  "code": 0,
  "data": {
    "user": { ... },
    "display_categories": [
      {
        "category_id": "0700000000000001",
        "category_name": "未分类",
        "labels": [
          {
            "label_id": "label_001",
            "label_name": "gender",
            "label_value": "男",
            "is_tagged": true
          },
          {
            "label_id": "label_002",
            "label_name": "age",
            "label_value": null,
            "is_tagged": false
          }
        ]
      }
    ]
  }
}
```

### 4. 打标接口（严格模式）

```
POST /insight/user-profile/{userId}/tag-label
```

**请求体**：
```json
{
  "label_id": "label_001",
  "label_value": "男"
}
```

**逻辑**：
- 只能选择已有标签（从 `profile_meta_label` 中选择）
- 提供"创建新标签"按钮，跳转到标签管理模块创建

## 打标模式：严格模式（业界标准）

### 打标流程

```
┌─────────────────────────────────────────────────────┐
│  打标签对话框                                        │
─────────────────────────────────────────────────────┤
│  选择已有标签（主要方式）                            │
│  [下拉搜索] gender  ▼                               │
│  标签值：[男________]                                │
│                                                    │
│  [+ 创建新标签] 按钮（辅助方式）                      │
│  点击后跳转到标签管理模块创建                        │
└─────────────────────────────────────────────────────┘
```

### 关键设计决策

| 问题 | 答案 |
|------|------|
| 可以对哪些标签打标？ | 只能选择 `profile_meta_label` 中已创建的标签 |
| 必须对已创建的标签打标吗？ | 是，严格模式 |
| 能不能对不存在的标签打标？ | 不能，但提供"创建新标签"按钮跳转到标签管理模块 |
| 打标后是否自动加入展示配置？ | 是，自动启用该标签的展示配置 |

## 前端 UI 设计

### 1. 展示标签按钮位置

```
[搜索框] [展示标签按钮] [打标签按钮]
```

### 2. 展示标签对话框（全局配置）

**左侧**：类目列表（带 checkbox）
**右侧**：标签网格（3 列），每个标签显示：
- Checkbox（是否启用展示）
- 标签名称
- 标签状态（已创建）

**底部**：
- 左侧：已选 X/Y [清空]
- 右侧：取消 / 确定

### 3. 详情页标签展示

**只展示全局配置为启用的标签**：
- 已打标：显示 `标签名：标签值`（蓝色背景）
- 未打标：显示 `标签名：-`（灰色背景，提示可打标）

### 4. 打标对话框

- 下拉选择已有标签（从 `profile_meta_label` 获取）
- 输入标签值
- 确定打标
- 提供"创建新标签"按钮，点击后跳转到标签管理模块

## 关键决策点

### Q1: 展示标签是全局配置还是每用户配置？
**A**: 全局配置。管理员统一设置哪些标签在画像详情页展示，所有用户共享同一配置。

### Q2: 打标模式是什么？
**A**: 严格模式。只能选择 `profile_meta_label` 中已创建的标签打标，提供"创建新标签"按钮跳转到标签管理模块。

### Q3: 展示标签是否包含未打标的标签？
**A**: 是。全局配置控制"显示哪些标签维度"，打标标签是"实际值"。详情页会显示配置的所有标签，有值显示值，无值显示"-"。

### Q4: 打标后是否自动加入展示配置？
**A**: 是。打标时自动将该标签加入全局展示配置（如果尚未配置）。

### Q5: 删除打标标签是否影响展示配置？
**A**: 否。展示配置保留，详情页显示为"未打标"状态。

### Q6: 标签元数据删除如何处理？
**A**: 软删除（`is_valid=0`），展示配置和打标记录保留历史数据。
